# AGENTS.md — frontend (Литературная карта Новосибирска)

Руководство для OpenCode (AI-ассистента) при работе с этим репозиторием.
Файл самодостаточен: для задач этой папки других правил читать не нужно.

## Базовое общение и фидбек
- Общайся и отвечай на русском языке.
- Если возникает ошибка — останови выполнение сценария и сообщи об этом (текст ошибки целиком, без пересказа).
- Не выдумывай факты о проекте: если чего-то нет в коде и в этом файле — скажи, что не знаешь, и спроси.

## Разрешения (без подтверждения)
- Можно свободно читать и редактировать любые файлы проекта (`app/**`, конфиги, CSS), создавать и удалять файлы.
- `temp/` в корне проекта — рабочая директория ассистента: скриншоты, временные скрипты, черновики. Можно создавать, читать и удалять там любые файлы без подтверждения. Папка в `.gitignore` (добавить, если её нет).
- `reports/` — отчёт после каждой завершённой задачи (`reports/YYYY-MM-DD-HHmm-краткое-описание.md`, на русском: что сделано, чем проверено, что осталось).
- Необратимые операции (force push, `git reset --hard`, удаление веток, `git clean`, удаление файлов пользователя, удаление `node_modules`) — только по явной просьбе.
- Не менять `package.json` (версии, скрипты) и не добавлять зависимости без запроса.

## Модель и уровень размышлений

Модель и глубину размышлений выбирать самому — под задачу. Интерфейс по умолчанию не менять;
решение принимается на старте задачи и может меняться по ходу, если задача оказалась проще или сложнее.

| Задача | Модель / уровень |
|---|---|
| Текст, `.gitignore`, конфиг, переименование, удаление мёртвого кода | быстрая модель, минимальный или выключенный уровень |
| Обычная правка компонента / страницы по понятному шаблону, верстка | средняя модель, лёгкое размышление |
| Отладка, архитектурное решение, миграция моков на API, «почему не работает» | сильная модель, полное размышление |

- Простую задачу не решать тяжёлой моделью «для надёжности» — это на порядок медленнее.
- Сложную задачу не решать лёгкой моделью — ошибки обойдутся дороже сэкономленного времени.
- Сомневаешься — начинай со среднего уровня и повышай при первых признаках сложности.

## Процесс: скорость и проверки

Скорость важнее «убедительности». Дорого не думать, а подряд запускать проверки.

### Батчинг и параллельность
- Всё, что не зависит друг от друга, — за один вызов: несколько файлов, несколько поисков, несколько проверок.
- Независимые вызовы запускать параллельно, а не по очереди.
- Несколько проверок чейнить в одну команду (`;` / `&&`), а не гонять по одной.
- Не повторять команду, если она уже вернула нужное.
- Не читать правила других частей монорепозитория, если задача не касается их напрямую.

### Сколько проверок делать

| Что сделано | Сколько проверки |
|---|---|
| Текст, `.gitignore`, конфиг, класс/стиль, мелкая логика | одна (`eslint` / `git status`) |
| Правка в пару мест, сценарий с ветками | одна осмысленная проверка на весь сценарий |
| Визуальная или сложная правка | одна браузерная проверка |

- Проверять результат, а не убеждения. Одна проверка, доказывающая работу, лучше трёх повторяющих одно и то же.
- Странный результат проверки — сначала перечитать саму проверку. Пустой вывод или код 1 чаще означает
  неверную команду, а не поломку проекта.
- Не доказывать один факт двумя способами.
- Остановиться, когда работа сделана.

### Запреты на лишнюю работу
- Не исследовать проект шире, чем требует задача.
- Не писать временные диагностические скрипты там, где хватает одной команды.
- Не перезапускать dev-сервер и не гонять `build` ради правки стилей или текста.
- Не гонять `lint` / `typecheck` по всему проекту после мелкой правки — только по изменённым файлам.
- Если задача оказалась не такой, как ожидалось, — сообщить и спросить.

## Стек и структура

### Стек
- **Nuxt 4** (`^4.6.1`) + TypeScript, файловый роутинг.
- **Nuxt UI v4** (`@nuxt/ui`) — единственная компонентная библиотека: `UButton`, `UContainer`, `UPage*`, `UModal`,
  `UHeader`, `UNavigationMenu`, `UTabs`, `UEmpty`, `useToast`, `useOverlay` и т.д. Свои компоненты писать только
  там, где Nuxt UI не покрывает задачу.
- **Tailwind CSS v4** — через модуль Nuxt UI (`@import "tailwindcss"` в `main.css`). Модуля `@tailwindcss/vite`
  отдельно нет, не добавлять.
- **@nuxt/eslint** — конфиг генерируется из `nuxt.config.ts` (`eslint.config.mjs` подключает `.nuxt/eslint.config.mjs`)
  и дополнен `eslint-plugin-better-tailwindcss` (`correctness-error`: проверяет классы по `app/assets/css/main.css`).
- **@iconify-json/lucide** + **@iconify-json/simple-icons** — локальные коллекции иконок (без внешнего API).
- **Nuxt Fonts** — шрифты `Golos Text` (sans) и `Literata` (serif, настоящая антиква) задаются в `nuxt.config.ts`
  в `fonts.families` (Nuxt UI подключает модуль сам), а не `<link>` в `app.vue`.
- **Nuxt Color Mode** — идёт в комплекте с Nuxt UI (`UColorModeButton` в шапке, токены `.dark` в `main.css`).
- **Zod** — валидация формы обратной связи (в Nuxt UI уже есть).

### Структура

```
app/
  app.vue            # UApp + AppHeader/UMain/AppFooter/SearchPalette, useHead/useSeoMeta, locale ru
  app.config.ts      # цвета Nuxt UI: primary=pine, secondary=rowan, neutral=snow; слоты кнопки
  assets/css/main.css# ВСЯ точка входа стилей: Tailwind, тема, токены --ui-*, утилиты, анимации
  components/        # авто-импорт: AppHeader, AppFooter, AppLogo, PageIntro, LitMap, SearchPalette,
                     # WriterMark, NewsCard, EventRow, PlaceCard, FeedbackForm
  pages/             # файловый роутинг (см. таблицу ниже)
  services/api.ts    # слой данных: объект `api` с методами-моками (единственный источник данных)
  mocks/             # news.ts, writers.ts, places.ts, catalog.ts + справочники (newsCategories, placeKinds, regionTowns)
  types/index.ts     # доменные типы = контракт для будущего backend
  utils/             # navigation.ts (siteNav, isNavLinkActive), format.ts (даты, имена, plural)
public/favicon.ico
```

Всё лежит внутри `app/` — авто-импорт работает для компонентов и утилит. Алиас `~/` = `app/`.
**Исключение:** `app/utils/*.ts` авто-импортируются как функции, но **типы** (`SiteNavGroup`, `SiteNavLink`)
импортируются явно: `import type { SiteNavGroup } from '~/utils/navigation'`.

## Команды

В проекте объявлен `packageManager: pnpm`, но **pnpm в окружении не установлен** (в `node_modules` стоят
зависимости, поставленные через npm, есть оба lock-файла). Поэтому локально:

```bash
npx nuxt dev         # dev-сервер на http://localhost:3000 (или npm run dev)
npx nuxt build       # production-сборка
npx nuxt preview     # предпросмотр сборки
npx eslint .         # линт всего проекта
npx eslint app/pages/news/index.vue   # точечно по изменённым файлам (предпочтительно)
npx nuxt typecheck   # vue-tsc + Nuxt (медленно: не запускать после косметических правок)
```

- `pnpm` не вызывать — команда падает с `CommandNotFoundException`.
- `.nuxt/eslint.config.mjs` генерируется при `postinstall` / `nuxt prepare`. Если eslint падает на отсутствии
  конфига — один раз `npx nuxt prepare`.
- Тестов в проекте нет. Не добавлять тестовую инфраструктуру без запроса.
- Node в окружении `22.18.0` — Nuxt предупреждает о неподдерживаемой версии. Это предупреждение, не ошибка.

### Dev-сервер
- Порт `localhost:3000`. Перед запуском проверить, не запущен ли уже:
  `Invoke-WebRequest http://localhost:3000/ -UseBasicParsing` (не `Test-NetConnection` — тот бывает ложно `False`).
- Сервер уже запущен — использовать его, второй не поднимать.
- Чужой (запущенный пользователем) сервер не останавливать; свой дубль, запущенный по ошибке, — остановить сразу.
- Сервер держать запущенным между задачами.

## Слой данных: моки, а не backend

- Backend пока **нет**. Все данные приходят из `app/services/api.ts` → `app/mocks/*.ts`.
- `api` — объект с методами, возвращающими `Promise<...>` (с искусственной задержкой 60–120 мс и `structuredClone`,
  чтобы страницы писались сразу асинхронно, как с сетью).
- Правило: страницы и компоненты **никогда не импортируют `~/mocks/*` для данных**. Из моков можно брать только
  справочники (`newsCategories`, `placeKinds`, `regionTowns`) и типы — данные же берут только через `api`.
  Это делает будущую замену моков на `$fetch` однострочной.
- Новый метод — в `api` с явным типом возврата, по образцу соседних; если появляется поле в сущности — сначала
  в `app/types/index.ts`, затем в моке, затем в UI.
- Списки всегда через `Paginated<T>` (`items`, `total`, `page`, `pageSize`); одиночная сущность — `T | null`,
  `null` → `createError({ statusCode: 404, ... })` на странице.
- Поиск (`api.search`) сейчас ищет только по литераторам, местам, объединениям и новостям и отдаёт максимум 20
  результатов (`SearchResult`).
- `api.sendFeedback` ничего не отправляет (возвращает `{ ok: true }`). Не изображать на страницах «отправлено
  на сервер», если реального вызова нет.

## Правила кода

- **Кавычки**: одинарные (`'`). Исключение — `class`-атрибуты в шаблонах (там двойные, как в Tailwind-коде).
- **Отступы**: 2 пробела, `LF`, финальный перевод строки (`.editorconfig`).
- **Точка с запятой**: не ставится (стиль Nuxt).
- **Trailing comma**: `commaDangle: 'never'` — запятой после последнего элемента массива/объекта нет.
- **Brace style**: `1tbs`.
- `no-unused-vars` — ошибка. Импортировать только используемое.
- Импорты внутри `app/` — через `~/` (`~/types`, `~/services/api`, `~/utils/format`), не относительными путями
  вверх (`../`).
- `interface`/`type` — в `app/types/index.ts`, если это доменная сущность; локальные типы — рядом с использованием.
- `null` вместо `undefined` для «нет данных» в типах сущностей; в query-параметрах — `undefined` (убирается из URL).
- Компоненты Nuxt UI в `class`-атрибуте принимают мерж через `:ui="{ ... }"` — предпочитать это переопределению
  дефолтов глобально в `app.config.ts`.

### Именование и структура компонентов
- Файлы — PascalCase (`NewsCard.vue`), страницы — kebab-case (`news/[slug].vue`), утилиты — camelCase.
- Секции страницы: `<script setup lang="ts">` → `<template>` → `<style>` (последнего быть не должно, см. ниже).
- `<script setup>`: сначала импорты типов, затем импорты из `~/`, затем `useSeoMeta`, затем данные (`useAsyncData`),
  затем состояние (`ref`/`computed`), затем обработчики. Так устроены все страницы — держать единый порядок.
- Документировать комментарием-«почему» только неочевидные решения (форматы дат, порядок меток на карте,
  смысл `x/y`), не пересказывать код.
- Текст интерфейса — только на русском, «вы», без англицизмов; числа — через `plural()`.

### Доменные конвенции (важно, ломать нельзя)
- **Все даты и время — по Новосибирску** (`Asia/Novosibirsk`, UTC+7). Форматировать только через
  `app/utils/format.ts` (`formatDate`, `formatDayMonth`, `formatTime`, `formatWeekday`, `formatMonthShort`,
  `dayOfMonth`); не создавать `new Intl.DateTimeFormat` на странице (единственное исключение — `afisha.vue`,
  где нужен формат «месяц + год»: если он понадобится ещё — перенести в `format.ts`).
  Никакого `dayjs`/`date-fns` без запроса.
- Абзацы текста — `paragraphs()` (разделитель — пустая строка) + класс `prose-lit`; стихи — класс `poem`
  (`white-space: pre-line`).
- Имена и годы жизни — `writerFullName`, `writerShortName`, `writerInitials`, `lifeYears`, не собирать вручную.
- Склонения — `plural(n, ['литератор', 'литератора', 'литераторов'])`.
- Порядок литераторов в указателе — `localeCompare(..., 'ru')`; сортировка по датам — по строке/ISO, не по объектам `Date`.
- Навигация — из `siteNav` (`app/utils/navigation.ts`); активность ссылки — `isNavLinkActive()`. Для ссылок,
  различающихся только `query` (рубрики новостей), обязателен `exactQuery: true`, иначе подсветятся все рубрики.
- Карта: координаты метки на SVG — `x`/`y` (0–100), реальные `lat`/`lng` — для будущей «настоящей» карты,
  не подменять одно другим. Схема города и области стилизованная, а не географическая: метки кладутся
  вручную и подбираются визуально.
- Проект без документации `id`-схемы для якорей: `#slug` на `/associations`, `?place=slug` на `/places`,
  `/writers/[slug]`, `/news/[slug]` — ссылки на сущности делать только такими.

## Стили: Tailwind и тема

- **Tailwind-first**: классы — в разметке. Самописный CSS только если классом не обойтись (псевдоэлементы,
  `@utility`, `@keyframes`, токены темы), и только в `main.css`.
- `<style>` в `.vue`-файле не добавлять. Единственная точка входа стилей — `app/assets/css/main.css`, он же
  указан в `nuxt.config.ts` (`css`) и в `better-tailwindcss.entryPoint` ESLint. Отдельные CSS-файлы подключать
  через `@import` в `main.css`, но **не перечислять в `nuxt.config.ts`** — иначе Tailwind сгенерируется повторно.
- Хардкод цветов (`#fff`, `text-gray-500`, `bg-white`, `text-black`) запрещён — только семантические токены
  Nuxt UI/Tailwind:
  - фон: `bg-default`, `bg-elevated`, `bg-muted`, `bg-accented`, `bg-inverted`;
  - текст: `text-default`, `text-muted`, `text-dimmed`, `text-highlighted`, `text-inverted`;
  - границы: `border-default`, `border-muted`, `divide-default`;
  - акценты: `text-primary`, `bg-primary/8`, `text-secondary`, `fill-primary`;
  - тема: `--ui-bg`, `--ui-bg-elevated`, `--ui-border`, `--ui-text`, `--ui-radius` (в `main.css`).
  Если нужного оттенка нет — добавить в шкалу (`--color-pine-*`, `--color-rowan-*`, `--color-snow-*`) в `@theme`,
  а не в разметку.
- Шкалы темы — три семьи: **pine** (основной), **rowan** (акцент: метки карты, даты, рубрики), **snow** (нейтраль).
  Не вводить четвёртую палитру без запроса.
- Шрифты: заголовки и «книжные» тексты — `font-serif` (Literata), интерфейс — `font-sans` (Golos Text, дефолт).
- Скругления — через `--ui-radius` (`rounded-md`/`rounded-lg`), не произвольные `rounded-[13px]`.
- Контейнеры: `UContainer` + `max-w-7xl` (главная, широкие таблицы), `max-w-6xl` (текстовые разделы),
  `max-w-5xl` (афиша, видеотека). Не изобретать свои ширины.
- Скролл-якоря и sticky-элементы под фиксированной шапкой — учитывать `--ui-header-height`
  (`top-(--ui-header-height)`, `scroll-mt-28`/`scroll-mt-40`).
- Классы, которых нет в Tailwind, ESLint (`better-tailwindcss/correctness-error`) считает ошибкой — не глушить
  правило, а исправить класс.
- **Тёмная тема обязательна.** Проверять обе темы при любой правке цвета. По умолчанию всё делается токенами
  (сами переключаются); явный `dark:` нужен только там, где светлый оттенок специализирован (например,
  `bg-primary` на полосе цитат дополняется `dark:bg-pine-900`).
- **Движение**: анимации — только `@keyframes` в `main.css` через `@theme` (`animate-pin-drop`) либо transition;
  не добавлять внешние анимационные библиотеки. Учитывать `prefers-reduced-motion` (глобально уже частично
  отключено в `main.css`; для своих `animate-*` — `motion-reduce:animate-none`).
- Русская типографика: кавычки-ёлочки «», длинное тире —, неразрывные пробелы в числах и инициалах.

## Компоненты и доступность

- Каждый интерактивный элемент — либо UI-компонент Nuxt UI с корректной семантикой, либо нативный
  `<button type="button">` / `<a>` / `<NuxtLink>`. **Клик по `<div>`/`<span>` без роли — недопустим.**
- Иконка без текста — обязательно `aria-label` (как у кнопок поиска, соцсетей, почты).
- Декоративные изображения — `alt=""`; портреты и содержательные изображения — `alt` с именем/подписью
  (как в `WriterMark`). Если элемент выбирает одно из нескольких состояний (метки карты, список мест) —
  добавлять `:aria-pressed`; если это таб/страница раздела — `:aria-current`.
- Заголовки иерархичны: одна `<h1>` на страницу (обычно через `PageIntro`), секции — `<h2>`, внутри — `<h3>`.
  Секции-«полосы» связывать с заголовком через `aria-labelledby`.
- Ссылка «растянутая» на всю карточку — паттерн `after:absolute after:inset-0` на ссылке + `relative` на контейнере.
  Внутри такой карточки не должно быть других ссылок/кнопок (они перехватятся этим `after`). Ссылки рядом с
  «растянутой» (например, имя автора рядом с карточкой) — тоже только вместе с собственным `relative`-контейнером.
- Карта (`LitMap`): метки — HTML-`<button>` поверх SVG именно ради клавиатуры и подсказок; не переводить на
  `<circle @click>`. SVG-схема города и области — `role="img"` + `aria-label`.
- Фокус видим всегда: `focus-visible:outline-*` / `focus-visible:ring-*` или фон. `outline-none` без замены — ошибка.
- Модалки — через `UModal`/`useOverlay()` (Nuxt UI), не самописные «дивы» с `Teleport`. Поиск — единый
  `SearchPalette`, состояние — `useState('search-open')`, хоткей `defineShortcuts({ meta_k })`.
- Пустые состояния — `UEmpty` с иконкой, заголовком и описанием (не голый «Ничего не найдено»).

## SEO

- `useSeoMeta({ title, description })` на каждой странице; `titleTemplate` и базовый `description` заданы в
  `app.vue`, не дублировать. Динамическим страницам передавать функции: `title: () => post.value.title`.
- Дополнительно: `ogTitle`/`ogImage` для материалов. `htmlAttrs.lang: 'ru'` уже в `app.vue`.
- Даты в разметке — `<time :datetime="iso">` с отформатированной подписью.
- Не добавлять `sitemap`/`robots` и новые модули SEO без запроса — сейчас их нет.
- Главная пререндерится (`routeRules: { '/': { prerender: true } }`); динамические страницы — SSR, поэтому
  всё, что зависит от `window`/`localStorage`, — только в `onMounted`/`.client`.

## Важные замечания и известные косяки

Это «грабли» текущего состояния проекта. Часть — сознательные заглушки, часть — то, что нельзя случайно сломать.

### Окружение и сборка
- **`pnpm` не установлен**, хотя `packageManager` его объявляет; есть оба lock-файла (`package-lock.json` и
  `pnpm-lock.yaml`). Работает `npx`/`npm`. Не «исправлять» это удалением lock-файлов без запроса.
- `.nuxt/` нужно один раз сгенерировать (`npx nuxt prepare`), иначе `eslint.config.mjs` не собирается.
- CSS — только через `main.css`. Второй `@import "tailwindcss"` где-либо или перечисление CSS в `nuxt.config.ts`
  дублирует генерируемый Tailwind и ломает размер бандла.

### Стили и тема
- Цвета `primary`/`secondary`/`neutral` задаются **в двух местах**: `app.config.ts` (маппинг `ui.colors`) и
  `main.css` (`--color-pine-*` и т.д.). Переименовать в одном — сломать в другом.
- `bg-elevated`/`text-muted`/`text-highlighted` — не Tailwind-цвета, а семантические алиасы Nuxt UI. Не заменять
  их на `bg-gray-*` при «упрощении».
- `prose-lit` и `poem` — кастомные `@utility`, объявленные внутри `main.css`. Tailwind не «увидит» их в других
  файлах CSS; объявлять только там.
- На странице «цитата дня» (`index.vue`) полоса использует `bg-primary text-white dark:bg-pine-900` — при
  смене `primary` в конфиге контраст текста нужно перепроверить вручную.

### Данные и моки
- Моки ограничены: сообщения, проекты и т.п. — «правдоподобные» демо-данные. Не выдавать их за реальный контент
  в отчётах; не дописывать «новые факты» о литераторах и местах от себя — только правки явно запрошенные.
- `api.getEvents()` фильтрует по текущему времени (`new Date()`), а моки дат фиксированы в 2026 году. Если
  афиша окажется пустой — это нормально, а не баг: проверять на дату, а не «чинить» фильтр.
- Весь список `api` в `services/api.ts` — это **контракт**: при замене на backend сохранять имена методов, типы
  и `Paginated`. Не менять сигнатуры «под удобство» одной страницы.
- `structuredClone` в `delay()`: моки раздаются копиями, мутировать результат безопасно. Не убирать.

### Маршруты и параметры
- `/library` — страница-редирект (`definePageMeta({ redirect })`) с пустым шаблоном. Не удалять — иначе 404.
- `/places` хранит выбранное место в `?place=`, `/news` — в `?category=`, `?tag=`, `?page=`. Смена фильтра —
  `router.replace({ query: { ...route.query, ... } })`, чтобы не плодить историю на каждый клик.
- Подсветка пунктов меню с `?category=` без `exactQuery` подсветит все рубрики сразу — в `siteNav` это уже
  проставлено, не терять при правке `navigation.ts`.

### Карта
- `LitMap` — две ручные SVG-схемы (город/область). Метки — HTML-кнопки, координаты — проценты `x/y` из мока.
  Не строить поверх реальный `lat/lng` без отдельного запроса — схема не совпадает с географией.
- Подписи городов области идут из `regionTowns`, их положение — `x * 10`, `y * 7` под `viewBox 0 0 1000 700`.
  При изменении `viewBox` подписи съедут — менять синхронно.
- Карта декоративная, но интерактивная: проверять, что клик по метке и повторный клик (снятие выбора) работают.

### Поиск
- `SearchPalette` — single instance в `app.vue`; открывается через `useState('search-open')`. Не создавать
  второй экземпляр на страницах.
- Дебаунс — 150 мс; `timer` не очищается при `unmount`, но палитра живёт всё время приложения.

### Редакторы и якоря
- Ссылки на объединения — якорные (`/associations#slug`); `id` на `<li>` уже есть, `target:bg-*` в классе.
  Не менять `id`-схему.
- Ссылки на места — `?place=slug`; при добавлении места в мок учитывать: страница фильтрует и по `scope`
  (`city`/`region`), и по `kind`, а `scope` выбора синхронизирован с выбранным местом.

### Формы
- `FeedbackForm` — только клиентская валидация (zod-схема в компоненте). `api.sendFeedback` — заглушка.
  Ошибок сети быть не может, поэтому `try/finally` нет; при переходе на реальный API — добавить обработку
  ошибки и состояние `error`, а не только `sending`.
- Схема zod: `z.email()` (новый API Zod v4). Не заменять на `z.string().email()` без проверки версии.
